# ROADMAP

What psephos is for, what has to be true before it can be trusted, and the order of the work.

Every item is a GitHub issue. Nothing here is a result.

## The state of the tool

Version 0.1 works. It loads precinct results, runs structural checks, tests for excess mass at
integer percentages, tests last-digit uniformity, measures the dependence between turnout and
vote share, and reports all of it stratified by precinct size. 47 tests, ruff clean.

**And it has never been run against a real election with a published result.** Every check is
implemented from a paper's description and tested only against synthetic elections generated by
this repository. That proves the code does what its author thinks the method is. It does not
prove the method was implemented correctly. Until [#6](https://github.com/Xocas12/psephos/issues/6)
is closed, psephos generates questions, not answers, and the README says so.

## The two failure modes this roadmap is organised around

A tool like this can fail in two opposite directions, and both are bad.

**Firing on honest data.** Small precincts, mixed populations, aggregation rounding and
transcription noise all produce the patterns these checks look for. A tool that flags them
launders a prior into a p-value and damages people who ran a clean election.

**Reassuring on dirty data.** A null from an underpowered test reads exactly like a clean bill
of health. Reporting it as one turns "we could not tell" into "there was nothing".

The milestones below attack the first through validation and adversarial review, and the second
through power analysis.

## Milestones

### v0.2 usable on real data

Nothing here is optional. Until this milestone closes, the honest description of psephos is
"an implementation of some published methods that has not been checked".

| Issue | Why it gates everything |
|---|---|
| [#6](https://github.com/Xocas12/psephos/issues/6) Validate against a real election with published results | The tool has never met real data. Reproduce a published figure, and separately measure behaviour on an election nobody disputes. |
| [#20](https://github.com/Xocas12/psephos/issues/20) Adversarial review | The guardrails were designed by the person who wrote the checks, which is the wrong person to evaluate them. |

| [#1](https://github.com/Xocas12/psephos/issues/1) Continuous integration | Nothing currently stops a change breaking the guardrail invariant. |

## The bar for a new check

Six things, and a check missing any of them will not be merged. The full version is
[#19](https://github.com/Xocas12/psephos/issues/19).

1. A null stated in one sentence.
2. A confounds list. Not optional: `Finding.__post_init__` raises without it.
3. **A quiet test.** The check must not fire on `clean_election()`. This is the one most often
   skipped and the one that matters most.
4. A loud test, where the measured effect rises with the injected amount.
5. A tested underpowered path.
6. A citation, or an explicit statement that the method is novel here.

## What psephos will not do

Recorded here so the decisions are visible rather than rediscovered.

- **No single fraud score.** Composite scores get quoted without their caveats and their
  weights are always arbitrary.
- **No first-digit Benford test.** See [#8](https://github.com/Xocas12/psephos/issues/8).
- **No anomalous-vote count** until the counterfactual is pinned down. See
  [#9](https://github.com/Xocas12/psephos/issues/9).
- **No error exit on a flagged finding**, so no script can turn "anomaly" into "failure".

## Related repositories

psephos is the standalone, general-purpose tool. It grew out of a research programme that
applies the same method families to elections, corporate accounting and official statistics:

| Repository | What it is |
|---|---|
| [forensics-core](https://github.com/Xocas12/forensics-core) | the research method library: digit tests, bunching at incentive notches, underdispersion, flow reconciliation, PU learning |
| [forensic-elections](https://github.com/Xocas12/forensic-elections) | Russian federal elections, the calibration project |
| [forensic-economy](https://github.com/Xocas12/forensic-economy) | accounting enforcement, Chinese provincial statistics, Soviet statistics |
| [gosplan-env](https://github.com/Xocas12/gosplan-env) | a multi-agent environment where reporting pathologies emerge from incentives |

Those repositories are research scaffolds under a discipline that forbids running anything
before its gate. psephos is deliberately the opposite: it is meant to be run. The two share
methods and not code, which is a live question tracked in
[forensics-core WO-112](https://github.com/Xocas12/forensics-core/issues/23).
